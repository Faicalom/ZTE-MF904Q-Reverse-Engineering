## GitHub: التنفيذ بعد المراجعة

1. افتح إنشاء مستودع واختر حسابك والاسم أعلاه. ابدأ Private للمراجعة؛ لا تضف رخصة تلقائية قبل قرارك.
2. ارفع محتويات مجلد المستودع نفسه مع الحفاظ على البنية، بما فيها README و01 و02 و03 وبقية المجلدات. لا ترفع أرشيف المشروع الخاص ولا صور firmware أو بيانات F المشفرة.
3. راجع قائمة الملفات في المتصفح، وابحث عن بيانات شخصية ومجلدات src والبصمات. استبدل YOUR_GITHUB_USERNAME باسمك الحقيقي، وجرب الروابط بعد الرفع. لا تترك رابطًا بديلًا بوصفه منشورًا.
4. بعد حسم LICENSE_REVIEW.md والتأكد من الملفات، غيّر الإتاحة إلى Public إذا أردت. هذا إجراء يدوي منك وليس جزءًا مما نُفذ هنا.
5. أنشئ مسودة Release للاستخراج بعلامة مستقلة مثل extraction-research-v0.1؛ أرفق ZIP الاستخراج وبصمته واستخدم ملاحظات إصداره. اذكر أنه source/research وليس حزمة تشغيل حي مكتملة.
6. أنشئ Release منفصلة لفتح البوتلودر مثل unlock-research-v0.1 مع ZIP الفتح وبصمته. لا تدمج executable واحدًا ولا ترفق LK/DA.
7. عند تصحيح README افتحه واختر التحرير، عدّل الرابط ثم احفظ التغيير برسالة واضحة. راجع الرابط من صفحة المستودع؛ تغيير النص لا ينشئ موضوع XDA تلقائيًا.
8. استخدم Issues للأخطاء المحددة وفعّل Discussions للأسئلة المفتوحة. لا تقبل raw dumps أو بيانات SIM في البلاغات.

هذه تعليمات موجزة لواجهة GitHub مع ملفات المشروع التفصيلية؛ راجع [إنشاء المستودع](https://docs.github.com/en/enterprise-cloud%40latest/repositories/creating-and-managing-repositories/creating-a-new-repository)، [إدارة الإصدارات](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)، و[Discussions](https://docs.github.com/en/discussions) عند تغير الواجهة.

## XDA

ادخل القسم المرشح وتحقق من عنوانه والقواعد المثبتة وشروط إنشاء الموضوع بحسابك؛ لم تستطع المراجعة الآلية قراءتها. ابحث داخل المنتدى عن MF904Q/M19-E وعن موضوع يخص العتاد نفسه، لا مجرد MF9xx. إن لم يثبت الموضع، توقف عن النشر هناك حتى تختار القسم الصحيح. بعد ذلك أنشئ موضوعًا جديدًا بعنوان ملف PROJECT والصق منشوره كاملًا، واستبدل رابط GitHub وارفق صورة PCB المسموحة. استعمل ملف HELP ردًا في الموضوع نفسه إذا منعت القواعد تكرار المواضيع؛ لا تنشئ إعلانين متطابقين.

## Reddit

افتح كل مجتمع واقرأ القواعد داخل حسابك قبل Create Post. اختر نوع المشاركة الذي يسمح به المجتمع. في hardwarehacking استخدم النص المخصص ورابط المشروع وصورة اللوحة مع caption صادق. في ReverseEngineering قدم رابط التحليل التفصيلي والعنوان العلمي، لا نص طلب مساعدة عامًا. [توضيح المشرف التاريخي](https://www.reddit.com/r/ReverseEngineering/comments/llfvrj/) مفيد لفهم الفرق لكنه ليس بديلًا للقواعد الحالية. لا تكرر الروابط على نحو دعائي، ولا تنشر شيئًا قبل أن تصبح روابط المقالات حقيقية.

## 4PDA

افتح الموضوع المرشح يدويًا واقرأ اسم الأجهزة والقواعد واللغة المقبولة. لا تنسبه إلىMF904Q دون دليل. إن كان الموضوع متوافقًا، سجّل الدخول واستخدم ردًا مرتبطًا بالمحادثة بدل إعلان منفصل؛ اختر النسخة الإنجليزية أو الروسية وفق القواعد الفعلية. النسخة الروسية محفوظة دون تغيير حدود الإثبات؛ لم نثبت أن الروسية إلزامية. إذا استمر403 أو لم يتضح تطابق الجهاز، تبقى الوجهة غير معتمدة.

## ما لا ينشر

لا صور المصنع أو DA أو الأرشيفات الخاصة حتى المشفرة، ولا RAWlogs أو هوية الجهاز أو كلمات المرور. الصورة الوحيدة المعتمدة هنا PCB component detail؛ لا تقل إن لدينا صورةLCD عربية منشورة أو اختبار ويب جديدًا. عبارات “B تعمل حاليًا” يجب أن تحمل تصنيف إفادة المستخدم ما لم يضاف سجل استرجاع أحدث. توجد أيضًا فروق مهمة بين انطفاء فعلي وإعادة تشغيل وفقدADB؛ لا تغيرها لجعل المنشور جذابًا.
